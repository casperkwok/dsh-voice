# 延迟测量

感知延迟按四段记录，单位毫秒。

| 段 | 定义 | 测量位置 |
|---|---|---|
| S1 | 用户最后语音帧到 VAD 确认静音 | 客户端麦克风帧时间戳与 VAD 事件 |
| wait | VAD 确认静音到提交话轮 | Host 状态机 |
| backend | 提交话轮到第一个音频帧送出 | Host TTS 队列 |
| S5 | 第一个音频帧送出到实际播放 | 客户端 WebAudio 排播时间 |

感知延迟 = S1 + wait + backend + S5。

测量方法：

1. 用固定音频素材回放，避免真人停顿不可控。
2. 同一素材同一配置跑 20 次，取中位数与 90 分位。
3. 每次改动只改一个变量，记录改动前后的置信区间。
4. 浏览器与电话链路分开统计，不混用数字。

## Phase 0 实测（2026-11-03）

环境：macOS（Darwin 25.5.0，Apple Silicon）· Chrome headless · 假麦克风 · localhost。

配置：ASR 为 zipformer bilingual，2 线程；VAD 为 Silero，最短语音 150ms，静音端点 600ms；TTS 为 VITS-zh-ll，4 线程；首段文本为「我听到了：」，5 个汉字。

| 指标 | 定义 | 次数 | 中位数 | 90 分位 | 最大 | 目标 | 结果 |
|---|---|---|---|---|---|---|---|
| TTS 首帧 | 首段文本送入到第一个音频分片 | 10 | 187ms | 202ms | 265ms | ≤ 300ms | 通过 |
| 感知延迟 | 用户最后语音帧到第一个音频分片 | 10 | 818ms | 828ms | 891ms | ≤ 1500ms | 通过 |
| VAD 静音确认 | 用户最后语音帧到 VAD 判定端点 | 10 | 619ms | 619ms | 619ms | 无独立目标 | 记录 |
| 打断停止 | 客户端检测到用户开口到停止播放 | 5 | 236ms | 250ms | 250ms | ≤ 300ms | 通过 |

补充数据：

- TTS 1 线程时首段 403–438ms，2 线程 216–279ms，4 线程 119–163ms；4 线程是首帧达标的关键配置。
- 长首段会拖慢首帧：同一模型 12 个汉字约 310–327ms，18 个汉字约 538–689ms（4 线程）。首段控制在 6 个汉字以内才能稳定低于 300ms。
- 直接向 WebSocket 灌 5.88 秒测试音频时，感知延迟 1079ms，TTS 首帧 185ms，打断停止 264ms；浏览器假麦克风路径的数字更稳定，因为帧按真实 20ms 节奏发送。

### 未覆盖

- 假麦克风没有真实扬声器回声，**AEC 与误打断率未验证**。
- headless Chrome 只验证了 WebAudio 排播，没有验证真实声卡输出。
- 只测了一台 macOS；Windows / Linux 与耳机 / 外放矩阵未测。
- TTS 首帧不包含 LLM 生成首句的时间；v0.1 接入 Agent 流式回复后需重测。

结论：本机、假麦克风路径的四项延迟目标全部通过。Phase 0 不能判定完成，还需要真机声学测试与三平台设备矩阵。
