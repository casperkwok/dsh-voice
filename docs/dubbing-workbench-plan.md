# 配音工作台规划

工作名：`dsh-dubbing-desk` / 配音台

日期：2026-11-06

## 1. 结论

做一个 **DSH 原生、多角色、可导演的配音工作台**，第一版只解决“台本 → 多角色音频”。

不做通用配音工具：VoiceStudio、voice-pro、pyVideoTrans、VideoLingo 已经把“能配音”做成免费能力。我们的差异是：

- 角色 casting，而不是选一个音色读全文
- 多 take 管理和单句重生成，而不是整段重做
- Agent 可以当导演：拆角色、分配音色、检查读音、对比 take
- 项目数据本地持久化，可回到任意一句
- 和 DSH 的媒体/设计工作台、语音运行时串成流水线

## 2. 目标与非目标

### 目标

1. 让一个 3–5 角色的短剧/口播台本，从粘贴到导出多轨音频不超过 30 分钟。
2. 单句重生成不超过 3 次点击，不重跑整篇。
3. 同一角色跨段落音色、语速、情绪保持一致。
4. 发音错误可被词典修正，不靠反复抽卡。
5. 项目可关闭、重开、继续改；数据不丢。
6. 云端 TTS 的字符成本可见，生成前可确认。

### 非目标（v1）

- 不做视频时间线、口型同步、自动剪辑。
- 不做声音克隆、声音设计；第三阶段再评估。
- 不做多人实时协作。
- 不做通用 TTS 朗读按钮；那是 `dsh-voice` 和现有 TTS 插件的职责。
- 不做配音演员交易市场。

## 3. 用户与场景

### 第一楔子

**多角色剧情 / 口播内容**

典型用户：

- 短剧/漫剧创作者：一集 2–5 分钟，3–6 个角色，情绪变化多。
- 小红书/抖音口播博主：单人口播，但需要不同语气和重录单句。
- 小团队内容编辑：写手写台本，另一个人做配音，需要交接和版本。

### 后续预设

| 场景 | 与第一楔子的差异 | 什么时候做 |
|---|---|---|
| 课程/企业培训 | 术语词典、章节、版本、多人协作 | v1 验证后 |
| 有声书 | 长文本、章节、旁白/角色分离、断句 | v1.5 |
| 跨境电商/出海视频 | 翻译、多语言、时长对齐、字幕 | v2 |
| 游戏 NPC | 角色批量台词、情绪标签、导出命名规范 | v2 |

人群不是产品边界，预设才是。底层是同一个项目、角色、take、导出模型。

## 4. 核心工作流

```
新建项目
  → 粘贴/导入台本
  → 自动识别角色
  → 角色 casting（音色、语速、情绪）
  → 批量生成 / 单句生成
  → 试听、对比 take、重生成
  → 修正发音
  → 导出多轨 WAV + 混音 WAV + SRT
```

关键原则：**任何一步都可以只改一句，不重跑全篇。**

## 5. 信息架构

侧边栏注册 `sidebar.panellist`，主区域注册 `main` keyed slot，页面 id 使用 `dubbing-desk`。

### 页面

| 页面 | 内容 |
|---|---|
| 项目 | 项目列表、最近打开、新建、导入、删除到回收站 |
| 台本 | 角色标签、台词编辑、场景分隔、字数/预计时长 |
| 角色 | 角色卡、音色、语速、情绪、试听句、锁定 |
| Take | 逐句 take 列表、试听、评分、备注、重生成 |
| 导出 | 混音/分轨、采样率、SRT、文件名规则、导出历史 |
| 设置 | 默认 provider、音色库、发音词典、成本上限、数据目录 |

### 首屏

首次进入不是空白页，而是“三步上手”：

1. 粘贴一段台本
2. 确认识别出的角色
3. 给每个角色选一个音色，生成第一段

## 6. 功能需求

### 6.1 项目

- 新建：标题、语言、内容类型预设（短剧/口播/课程/有声书）。
- 项目数据独立目录，支持重命名、复制、归档、删除到回收站。
- 自动保存，崩溃恢复；写入使用临时文件 + 原子替换。
- 项目级默认：provider、输出采样率、角色默认语速。

### 6.2 台本导入与解析

支持：

- 纯文本粘贴
- `.txt` / `.md` 导入
- v1 不做 DOCX/PDF；后续加。

解析规则：

- `角色：台词` / `角色: 台词` → 该角色台词。
- `（情绪）` / `(情绪)` 开头或行内 → 情绪提示。
- 空行或 `## 场景` → 场景分隔。
- 无法识别角色的行 → 旁白（Narrator）。
- 保留原文标点；不自动改写台词。

解析后进入“角色确认”界面，允许合并/拆分/改名角色，避免把“旁白：”识别成角色。

### 6.3 角色与 casting

每个角色：

- 名称、颜色、备注、默认音色、默认语速、默认情绪。
- 音色来源：本地 Kokoro / Matcha / VITS；云端火山 / 阿里百炼 / MiniMax。
- 试听句：用该角色当前音色读一句固定台词，可换成用户输入。
- 锁定角色音色，避免批量生成时误改。

casting 视图：

- 左侧角色列表，右侧音色库；点一个音色立即试听。
- 同一句台词横向对比 2–4 个音色。
- 角色音色变更只影响后续生成；已有 take 保留，标注“旧音色”。

### 6.4 生成与 take

生成单位：**segment**（一句台词）。

- 单句生成、选中多句生成、整篇生成。
- 队列串行/有限并发；按 provider 限流。
- 每个 take 记录：provider、voice、speed、emotion、字符数、预计成本、实际耗时、音频路径、状态。
- 失败重试；保留错误原因；单句失败不阻塞其他句。
- take 可评分（1–5）、写备注、设为当前版本。
- 重生成时可调整：音色、语速、情绪、停顿、发音词典。
- 支持“只重生成选中文本”，不重跑前后句。

### 6.5 发音词典

- 项目级 + 全局级。
- 条目：`词`、`读音/替换文本`、备注。
- 生成前应用；UI 显示命中的词。
- v1 只做字面替换；后续正则和音素级。
- 避免全局替换误伤，按最长词优先。

### 6.6 音频与导出

v1 内置 WAV 处理，不依赖 ffmpeg：

- 每个 take 存 WAV。
- 按段落拼接，插入可配置停顿。
- 输出：
  - 混音 WAV
  - 每个角色一条分轨 WAV
  - SRT（按段落/句子时间）
  - 项目清单 JSON

后续可选 ffmpeg：

- MP3/M4A
- 视频导入、背景音乐 ducking、MP4
- 响度标准化（-16 LUFS 等）

采样率统一到 24kHz；不同 provider 的 16k/32k 输出先重采样。v1 用高质量 JS 重采样库或 sherpa 的重采样能力，避免引入 ffmpeg。

### 6.7 成本与 provider

- 每个 provider 维护价格表（字符/千字），可在设置中改。
- 生成前显示：预计字符数、预计成本、当前 provider。
- 超过项目预算阈值需要确认。
- BYOK：Key 只在本机，沿用 `dsh-voice` 的 0600 设置文件模式。
- provider 失败自动回退顺序可配置；回退前不重复计费已成功的段落。

### 6.8 Agent 工具

模型可调用：

| 工具 | 作用 |
|---|---|
| `dubbing_create_project` | 建项目、设语言/预设 |
| `dubbing_parse_script` | 导入台本并返回角色列表 |
| `dubbing_cast_roles` | 按角色描述推荐音色，写回项目 |
| `dubbing_generate` | 生成指定段落/整篇 |
| `dubbing_regenerate` | 单句换参数重生成 |
| `dubbing_review` | 汇总失败、成本、时长、未生成段落 |
| `dubbing_export` | 导出混音/分轨/SRT |

Agent 不能静默产生云费用：调用生成工具前必须带预算确认，或项目已设置自动批准上限。

## 8. 架构

### 代码组织

在现有 `dsh-voice` monorepo 内新增：

```
packages/
├── voice-core/          # 抽出的 TTS 适配器、模型管理、音频工具
├── voice/               # 现有全双工语音插件
└── dubbing-desk/        # 配音工作台插件
```

`voice-core` 先抽：

- `tts/volc.ts`、`tts/dashscope.ts`、`tts/minimax.ts`
- `models.ts` 的模型下载/状态
- `AudioChunk`、`pcmRms`、WAV 编码/重采样/拼接

`dsh-voice` 改为依赖 `voice-core`，行为不变。`dubbing-desk` 也依赖它。

### Host

```
src/host/
├── project-store.ts     # 项目读写、锁、回收站
├── script-parser.ts     # 角色/场景/情绪解析
├── voice-catalog.ts     # 音色库与 provider
├── job-queue.ts         # 生成队列、限流、重试
├── audio-render.ts      # 重采样、拼接、混音、SRT
├── lexicon.ts           # 发音词典
├── exports.ts           # 导出
└── routes.ts            # /dubbing/* HTTP API
```

### Client

```
src/client/
├── index.tsx            # main + sidebar.panellist + settings.section
├── Desk.tsx             # 主页面
├── Projects.tsx
├── ScriptEditor.tsx
├── Casting.tsx
├── Takes.tsx
├── Export.tsx
├── SettingsCard.tsx
└── store.ts
```

DSH 集成点：

- `main` keyed slot：整页工作台。
- `sidebar.panellist`：侧边栏入口，label 跟随语言。
- `settings.section`：设置页“配音台”。
- Host HTTP 路由：`/dubbing/projects`、`/dubbing/parse`、`/dubbing/generate`、`/dubbing/takes`、`/dubbing/export`。
- Agent tools：通过 DSH tool 服务注册；只读写项目目录。
- 项目存储：`$DSH_HOME/dubbing-desk`，不写工作区，除非用户导出。

## 9. 技术选择

| 项 | 选择 | 理由 |
|---|---|---|
| 项目存储 | JSON + 文件 | 无数据库迁移，易备份/导出 |
| 音频 | WAV + JS 重采样/拼接 | v1 不强制 ffmpeg |
| 队列 | Host 内存队列 + 项目锁 | 单机足够；重启后恢复未完成任务 |
| TTS | `voice-core` 多 provider | 复用现有适配器 |
| 本地 TTS | Kokoro fp32 / Matcha / VITS | 已有模型与下载 |
| 云端 TTS | 火山 / 百炼 / MiniMax | 已有适配器 |
| UI | React + DSH slots | 与 DSH 一致 |
| 数据 | 本地优先 | 隐私和可迁移 |

## 10. 里程碑

### Phase 0：1 周 spike

目标：验证“多角色台本 → 多轨音频”是否省时间。

- 用 3 个真实短剧/口播台本，每个 3–5 角色。
- 命令行/最小页面：解析角色、分配音色、逐句生成、拼接 WAV。
- 输出：10 分钟内完成一集 2 分钟音频。
- 记录：每句生成耗时、失败率、重生成次数、总耗时。

**Go/No-Go**：如果比现有工具（剪映/配音工具）没有 30% 以上时间节省，暂停。

### Phase 1：2–3 周 MVP

- DSH 插件骨架：侧边栏 + 主页面 + 设置页。
- 项目、台本解析、角色 casting、逐句生成、take 列表、WAV/SRT 导出。
- 成本显示、失败重试、项目持久化。
- 只支持中文；只支持短剧/口播预设。
- 验收：50 段、5 角色台本，全流程不丢数据；单句重生成 ≤ 3 次点击。

### Phase 2：3–4 周 视频与翻译

- 导入 MP4/MP3；ASR + 说话人分离；字幕对齐。
- 翻译 + 多语言配音；时长适配。
- 时间轴、背景音乐 ducking、MP4 导出。
- 需要 ffmpeg，作为可选依赖提示安装。

### Phase 3：2–4 周 规模化

- 声音克隆（BYOK/本地）与同意书、审计。
- 团队协作、项目版本、批量任务。
- 插件市场、npm、英文 UI。
- 付费：团队/托管渲染/商用授权。

## 11. 验收指标

| 指标 | 目标 |
|---|---|
| 首次出音频 | 3 角色 10 句，≤ 3 分钟 |
| 单句重生成 | ≤ 3 次点击 |
| 生成成功率 | ≥ 95%（失败可重试） |
| 数据丢失 | 0（崩溃/重启后项目可恢复） |
| 成本可见 | 生成前显示预计字符/费用 |
| 导出 | 混音 WAV + 分轨 + SRT 全部成功 |
| 用户时间 | 比手工配音/剪映流程节省 ≥ 30% |

## 12. 风险

| 风险 | 处理 |
|---|---|
| 免费竞品强 | 不打“通用配音”，打多角色 casting + DSH 工作流 |
| 云 TTS 成本/限流 | BYOK、成本预估、队列限流、失败回退 |
| 声音克隆合规 | v1 不做；后期同意书、水印、审计 |
| 长音频内存 | 分段渲染、流式拼接、导出分块 |
| ffmpeg 依赖 | v1 不依赖，MP4/MP3 作为可选 |
| DSH API 变化 | `voice-core` 隔离；0.2.x/0.3.x 兼容测试 |
| 项目数据损坏 | 原子写、备份、导出清单 |

## 13. 第一周要做的事

1. 选 3 个真实台本：短剧、口播、课程各一。
2. 用现有 TTS 适配器跑通“角色 → 逐句 WAV”命令行。
3. 做最小拼接：停顿、混音、分轨、SRT。
4. 记录每句耗时、失败、重生成次数、总时间。
5. 找 3 个真实用户试用，问一句：愿不愿意为“省下来的时间”付费。

一周后只回答一个问题：**它是不是真的比现在的做法省时间？** 不是就停，是就进 MVP。

## 14. 已定决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 做 DSH 插件，不先做独立桌面端 | 先借 DSH 的分发、Agent 和会话数据；桌面端等需求验证后再做 |
| 2 | 第一版只做“台本 → 多角色音频” | 视频时间线成本高，先把角色 casting 和 take 管理跑通 |
| 3 | 不做声音克隆 | 合规和审核成本高；先用现成音色验证工作流 |
| 4 | 项目数据放 `$DSH_HOME/dubbing-desk` | 不污染工作区，便于备份和迁移 |
| 5 | TTS 走 `voice-core`，与 dsh-voice 共用 | 避免复制三套云端适配器 |
| 6 | v1 不强制 ffmpeg | 降低安装门槛；MP3/MP4 后置 |

## 17. 开放问题

1. 第一楔子到底是短剧还是课程？目前倾短剧，因为多角色和 take 需求最强；用 3 个真实项目验证。
2. 默认本地还是云端？默认本地 Kokoro 做试听，正式生成让用户选 provider。
3. 是否需要分轨导出？短剧团队通常需要；先做，成本不高。
4. 是否要支持说话人分离？v1 不做；视频阶段再做。
5. 是否开放 Voice Intent 给其他插件？等 dubbing 工作台验证后再定，避免过早抽象。
